# Security policy

This is a local research prototype, not a clinically validated medical device.
Only the current main branch receives best-effort fixes. There are no supported
production releases or response-time guarantees.

## Reporting

Use GitHub's private vulnerability reporting option under Security > Advisories
if it is enabled for this repository. Enabling it is a maintainer settings task
and has not been verified. If unavailable, open an issue asking for a private
reporting channel without including vulnerability details, data or exploits.
Do not post patient information or credentials in issues.

## Trust boundaries

Joblib uses pickle and can execute code on load. The demo loads only the fixed
local model generated by scripts/train_baseline.py. Never replace it with an
untrusted download; no model-upload endpoint is provided. NPZ archives use
allow_pickle=False but still consume memory; use trusted local archives.

Run Streamlit on 127.0.0.1 for local use. EDF uploads are limited to 50 MiB and
preprocessing rejects recordings above 50 million decoded samples before
get_data. These bounds are not a security sandbox; hostile binary files and
multi-user deployment require isolation and resource limits beyond this app.

Downloads require SHA256 matches and paths contained in the raw-data directory.
A checksum fetched from the same HTTPS origin is integrity evidence, not an
independent signature. Do not let untrusted users modify local paths during a
run. Local writable directories and models are trusted.

Dependency audits report known advisories, not proof that software is secure.
Run python -m pip_audit --local after installation. The unpublished local
package may be skipped by the advisory database. Review update PRs and rerun
tests before merging. GitHub workflows have read-only repository permissions.
